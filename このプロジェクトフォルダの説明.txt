このプロジェクトフォルダの説明
更新日: 2026-09-11

======================================================================
1. このフォルダは何か
======================================================================

このフォルダは、Java、React、Python、FastAPI、PostgreSQL、Docker、
Google Cloudを使う受託開発案件の面談対策・学習用ワークスペースです。

主な目的は次の3つです。

1. スキルシートに記載した2案件の内容を、小さなアプリで理解する。
2. ReactからBackend APIを呼び、PostgreSQLへ保存する流れをコードで追う。
3. workflow-apiをGoogle Cloudへ実際にDeployし、Cloud Run、Cloud Logging、
   Cloud SQL、Artifact Registryの画面と操作を体験する。

商用品質の完成品を作ることが目的ではありません。
面談で「どの層が何をしているか」「テストで何を確認するか」
「GCP上でどこを見て調査するか」を説明できることを優先した教材です。


======================================================================
2. 最初に理解しておくべき重要な区別
======================================================================

このフォルダには、次の3種類の情報があります。

【A. 実際の案件・経歴に関する原情報】
スキルシート、案件票、提案メールなどに書かれた内容です。
面談で経歴として説明するときの根拠になります。

【B. 学習用に小さく具体化した実装】
backend/、frontend/、task-management-fastapi/のコードです。
実案件の構造をそのまま複製したものではありません。
例えば、H2、SQLAlchemy、Repository Pattern、
TODO / IN_PROGRESS / DONEといった具体的な状態名は、
教材を成立させるための選択です。Spring Data JPAは1件目で使用した固定情報です。
これらを「実際の現場で使っていた」と断定してはいけません。

【C. 今回の学習で実際に行ったGCP操作】
2026-09-09から2026-09-10に、学習用Project上でArtifact Registry、
Cloud Run、Cloud Logging、Cloud SQLを実際に操作した記録です。
画面と検証結果はExcelとoutput/配下に残っています。

詳細な線引きはPROJECT_CONTEXT.mdを参照してください。


======================================================================
3. ここまでに行ったこと
======================================================================

【1. 案件資料の整理】

- 顧客受託開発案件の必須スキルを確認した。
- スキルシートの2案件を、実績と教材上の仮定に分けて整理した。
- Java / Spring Boot / React / GCPを最優先とし、FastAPIやTestと比較しながら
  学ぶ順番を作成した。

【2. 1件目の学習用アプリを作成】

「法人向け申請・ワークフロー管理システム」を小さく再現した。

実装した業務は次の3つです。

- 申請を登録する。初期状態はPENDING。
- 申請一覧を表示する。
- PENDINGの申請をAPPROVEDへ変更し、承認履歴を1件保存する。

データの流れ:

React + TypeScript
  -> HTTP / JSON
Spring Boot Controller
  -> Application Service
Spring Data JPA Repository
  -> PostgreSQL

承認処理では@Transactionalを使い、申請の状態更新と履歴登録を
同じ1Transactionとして扱う構成にした。

【3. 1件目のTestを作成】

- Backend: JUnit 5 + Mockito
  ApplicationServiceは本物、RepositoryはMockにし、正常承認、対象なし、
  承認済みの再承認をTestする。
- Frontend: Jest + React Testing Library
  一覧取得、登録API、PENDING時の承認button、APPROVED時の非表示、
  API Error表示、処理中buttonの無効化をTestする。

【4. 2件目の学習用アプリを作成】

「法人向け業務依頼・進捗管理Webシステム」をtask-management-fastapi/に作成した。

実装した主な機能:

- Taskの一覧、登録、検索。
- 担当者と期限の更新。
- TODO -> IN_PROGRESS -> DONEの状態遷移。
- 対象なし、不正な状態遷移、入力エラーの応答。

構成:

React + TypeScript
  -> HTTP / JSON
FastAPI Router
  -> TaskService
TaskRepository
  -> SQLAlchemy
PostgreSQL

Backendはpytest、FrontendはJestでTest codeを用意した。

【5. 2案件の比較資料を作成】

- Spring BootとFastAPIのレイヤーと記述方法の比較。
- JUnit / Mockito / Jest / React Testing Library / pytestの役割の比較。
- 30分、60分、90分で復習する場合の学習順序の作成。

【6. workflow-apiをGoogle Cloudへ実際にDeploy】

ブラウザ操作にはChromeの「CT用」Profileのみを使用した。
Localにgcloudがなかったため、Google Cloud Consoleとブラウザ内Cloud Shellを使用した。

実施した流れ:

1. 学習専用Google Cloud ProjectとBillingを確認。
2. Project全体の100円BudgetとCloud Run用Spend Capを設定。
3. backendをCloud ShellへUpload。
4. Docker ImageをBuildし、Artifact RegistryへPush。
5. H2 ProfileでCloud RunへDeploy。
6. ID Token付きでGET、POST、承認APIを実行。
7. Cloud LoggingでRequest LogとApplication Logを確認。
8. Cloud SQL for PostgreSQLを最小・低コスト構成で作成。
9. Cloud RunからCloud SQLへJava Connectorで接続。
10. 意図的にDB Passwordを間違えたRevisionを作り、起動失敗を発生。
11. Logs Explorerでroot causeを特定。
12. 正しい設定の新RevisionをDeployし、復旧を確認。

【7. GCP操作の画面教材を作成】

- Billing、Budget、Artifact Registry、Cloud Run、Logging、Cloud SQLの画面を撮影。
- Service URL、IP Address、Account情報などを不透明の黒マスクで隠した。
- PasswordはExcel、Screenshot、Logに記録していない。
- マスク前の画像は成果物から削除した。
- 7Sheet構成のGCP_画面操作_面談対策.xlsxを作成。
- 画像が小さかったため、操作Sheetの画像、行高、列幅を拡大した。
- 面談チェックSheetの11問それぞれに、該当画面を追加した。
- Artifact Toolで作成し、Sheet Render、LibreOffice PDF変換、数式エラー検査を行った。

7. Localで動かす方法
======================================================================

【1件目: Spring Boot + React + PostgreSQL】

このフォルダのRootで実行:

  docker compose up --build

起動後:

- React: http://localhost:3000
- Spring Boot API: http://localhost:8080
- PostgreSQL: localhost:5432

停止するだけ:

  docker compose down

DBの学習データも削除:

  docker compose down -v

注意: -vはPostgreSQL volumeを削除します。

【2件目: FastAPI + React + PostgreSQL】

  cd task-management-fastapi
  docker compose up --build

起動後:

- React: http://localhost:3001
- FastAPI Swagger UI: http://localhost:8000/docs
- PostgreSQL: localhost:5433

停止:

  docker compose down

DBデータも削除:

  docker compose down -v

8. Testの実行方法
======================================================================

【Spring Boot Backend】

  docker build --target build -t workflow-backend-test ./backend

Dockerfileのbuild stage内でmvn packageが実行され、JUnit Testも実行されます。

【Spring Boot側React Frontend】

  docker build --target build -t workflow-frontend-test ./frontend
  docker run --rm workflow-frontend-test npm test

【FastAPI Backend】

  cd task-management-fastapi
  docker compose run --rm backend pytest -q

【FastAPI側React Frontend】

  cd task-management-fastapi
  docker build --target build -t task-frontend-test ./frontend
  docker run --rm task-frontend-test npm test

テストコードは存在しますが、この説明ファイル作成時に再実行したわけではありません。
最新の成否が必要な場合は上記commandで実行してください。

9. GCP Resourceを面談後に削除する手順
======================================================================

この操作はCloud上のデータとResourceを削除します。
現在状態を確認し、対象Project IDがworkflow-gcp-learn-260909-rk82であることを
確認してから実行してください。

推奨順序:

1. Cloud SQL Instance workflow-dbを最優先で削除。
2. Cloud Run Service workflow-apiを削除。
3. Artifact Registry Repository workflow-repoを削除。
4. Service Account workflow-runnerを削除。
5. Cloud ShellにUploadしたZIPと展開済みbackendを削除。
6. Cloud SQL、Cloud Run、Artifact Registryの一覧で残存Resourceを再確認。
7. Billing Reportを確認。表示遅延を考慮する。
8. 最後に学習専用Projectを削除。

CLI例:

  gcloud config set project workflow-gcp-learn-260909-rk82
  gcloud sql instances delete workflow-db
  gcloud run services delete workflow-api --region=asia-northeast1
  gcloud artifacts repositories delete workflow-repo --location=asia-northeast1
  gcloud iam service-accounts delete workflow-runner@workflow-gcp-learn-260909-rk82.iam.gserviceaccount.com

最後のProject削除は不可逆な操作です。
他のProjectを選んでいないことを必ず再確認してください。

12. ソースコード管理の現状
======================================================================

このRootフォルダは学習用のlocal Git Repositoryとして初期化します。
`main`と`completed`は完成版、`test-practice`は2つの練習Testに各1箇所のTODOを置くbranchです。

.gitignoreで除外する主な対象:

- IDE設: .idea/ / .vscode/
- macOS生成物: .DS_Store
- Java build生成物: backend/target/
- Frontend dependency / build生成物: frontend/node_modules/ / frontend/dist/
- GCP Screenshot、Excel、案件資料、提案文、認証情報に該当し得るFile

今後Gitで管理する場合は、個人情報、Screenshot、Excel、案件資料を
どこまで含めるかを決め、公開範囲に合わせて.gitignoreを見直してください。
